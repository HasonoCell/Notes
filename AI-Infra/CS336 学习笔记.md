# 语言模型、Tokenizer、PyTorch

语言模型（Language Model）要解决的核心问题很简单：给定已经出现的内容，预测下一个 token。比如完整序列是：

    我 喜欢 猫 <结束>

训练时把同一个序列错开一位，得到输入和目标：

    输入 x： 我     喜欢    猫
    目标 y： 喜欢   猫      <结束>

也就是说，目标 token 总是输入 token 的下一个 token。对于真正能够理解上下文的模型，可以把这理解成：看到“我”后预测“喜欢”，看到“我 喜欢”后预测“猫”，看到“我 喜欢 猫”后预测“<结束>”。不过，下面要实现的极简模型还没有 Transformer，它实际上只能看到当前位置的 token，因此只能学习“我 → 喜欢”“喜欢 → 猫”这样的独立映射，暂时不能真正利用“我 喜欢”这个完整前缀。**这也是为什么 Transformer 如此重要的原因～**

整个过程可以先记成一条主链路：

    文本 → Tokenizer → token ID → Tensor
         → Embedding → 向量 → Linear → logits
         → loss → 梯度 → 更新参数

### 1. Tokenizer 与语言模型的训练数据

神经网络不能直接处理字符串，所以需要 Tokenizer 把文本切分成 token，再把每个 token 转换成整数编号：

    文本 → token → token ID

例如，某个词表可能规定：

    我 → 12，喜欢 → 35，猫 → 87

于是：

    encode("我喜欢猫") → [12, 35, 87]
    decode([12, 35, 87]) → "我喜欢猫"

`encode` 完成文本到 token ID 的转换，`decode` 完成 token ID 到文本的转换。Tokenizer 负责建立“字符串和整数编号”的对应关系，Embedding 才负责把整数编号转换成可学习的向量

最简单的字符级 Tokenizer 可以把每个字符作为一个 token。现代语言模型通常使用子词 Tokenizer（Subword Tokenizer），例如 BPE（Byte Pair Encoding）：常见的字符组合会逐渐合并成较大的 token，常见词可以用较少的 token 表示，生僻词仍然可以拆成更小的片段。词表中还经常有一些特殊 token，例如 `<unk>` 表示无法识别的 token，`<eos>` 表示序列结束，`<pad>` 用于把不同长度的序列补齐到同样长度。

Tokenizer 输出的是整数索引，所以传给 `nn.Embedding` 时通常使用 `torch.long`：

~~~python
token_ids = torch.tensor([12, 35, 87], dtype=torch.long)
~~~

语言模型训练时，通常会把很多条长度相同的 token 序列组成一个 batch。后面反复出现的几个字母约定如下：

    B：batch size，一次处理多少条序列
    T：sequence length，每条序列包含多少个位置
    D：embedding/hidden dimension，每个位置的向量长度
    V：vocabulary size，词表中 token 的数量

因此，一批输入通常是 `[B, T]`，目标也是 `[B, T]`；模型在每个位置都对整个词表进行预测，输出形状是 `[B, T, V]`。

### 2. Tensor、Embedding 与 Linear：从编号到词表分数

PyTorch Tensor 可以看成多维数值数组，但它还支持向量化运算、GPU 计算和自动求导。它的形状可以表示不同层次的数据：标量的 shape 是 `[]`，向量是 `[D]`，矩阵是 `[M, N]`，一批序列的向量则可以是 `[B, T, D]`。常用属性包括 `x.shape`、`x.ndim`、`x.dtype` 和 `x.device`。

Tensor 的索引从 0 开始。假设：

    token_ids = [
        [1, 3, 4],
        [2, 3, 5],
    ]

那么 `token_ids[0, 1]` 的结果是 `3`，表示第 0 句话的第 1 个位置，也就是第一句话的第二个 token 的 ID。

需要区分两种常见的乘法：`a * b` 是对应位置相乘，要求形状能够广播；`a @ b` 是矩阵乘法，例如 shape 为 `[4, 5]` 的矩阵乘 shape 为 `[5, 2]` 的矩阵，结果 shape 为 `[4, 2]`。中间的两个维度 `5` 必须匹配，外侧的 `4` 和 `2` 决定结果形状。（想起了线性代数一些不好的回忆......)

Embedding 可以理解成一张可学习的查表。假设词表有 `V` 个 token，每个 token 用 `D` 个数字表示：

    embedding = nn.Embedding(num_embeddings=V, embedding_dim=D)
    embedding.weight.shape == [V, D]

表的第 `i` 行就是 token ID 为 `i` 的向量。如果 `token_ids[0, 1] == 3`，那么：

    embedding(token_ids)[0, 1] == embedding.weight[3]

也就是说，Embedding 不是根据 token ID 做复杂计算，而是根据 ID 取出对应的那一行。假设输入 `token_ids` 的 shape 是 `[2, 3]`，查表后输出的 shape 就是 `[2, 3, D]`：原来的每个整数位置，都被替换成了一个 `D` 维向量。

这些向量一开始通常是随机的，训练过程中会根据 loss 产生的梯度逐渐调整。向量的价值在于它是连续的数值表示，后面的 Linear 等层可以对它做点积、加权和并通过梯度学习

Linear 接着把每个 `D` 维向量转换成 `V` 个数字。因为 `out_features` 被设置成词表大小，所以这 `V` 个数字可以按照词表编号解释（注意是人为地去“解释”哦）为每个候选 token 的分数：

    linear = nn.Linear(in_features=D, out_features=V)
    [B, T, D] → [B, T, V]

Linear 本身并不知道“第 0 个输出代表哪个词”，它只负责输出数字；是词表 ID 的约定让我们把第 `i` 个输出解释成 token `i` 的分数。对于一个输入向量 `h`，PyTorch 中 Linear 的参数形状通常是：

    linear.weight： [V, D]
    linear.bias：   [V]

如果把输入写成列向量，计算可以写成 `logits = W @ h + b`；如果把输入写成行向量，则写成 `logits = h @ W.T + b`。展开来看，第 `i` 个候选 token 的分数就是：

    logits[i] = h · W[i] + b[i]

因此，`W` 的每一行都可以看成一个候选 token 的独立打分器。具体地，假设：

    h = [2, -1, 0.5]

    W =
    [
        [ 1,  0, 2],   # token 0
        [ 0,  1, 1],   # token 1
        [ 0, -1, 2],   # token 2
        [-1,  1, 0],   # token 3
    ]

忽略 bias 时，四个分数分别是：

    token 0：2×1 + (-1)×0 + 0.5×2 = 3
    token 1：2×0 + (-1)×1 + 0.5×1 = -0.5
    token 2：2×0 + (-1)×(-1) + 0.5×2 = 2
    token 3：2×(-1) + (-1)×1 + 0.5×0 = -3

所以 `logits = [3, -0.5, 2, -3]`，分数最高的是 token 0。Linear 并不是把一个向量直接“变成了某个 token”，而是用 `V` 套不同的打分公式，同时评估词表中的 `V` 个候选 token。对 `[B, T, D]` 的输入，Linear 会对最后一个维度独立执行同样的计算，所以每个 batch、每个位置都会得到一组 `[V]` 分数。

把两层连起来看，代码和形状就是：

~~~python
import torch
from torch import nn

B, T, V, D = 2, 3, 4, 8
token_ids = torch.tensor([[0, 1, 2], [1, 2, 3]], dtype=torch.long)

embedding = nn.Embedding(num_embeddings=V, embedding_dim=D)
linear = nn.Linear(in_features=D, out_features=V)

hidden = embedding(token_ids)  # [2, 3]     → [2, 3, 8]
logits = linear(hidden)        # [2, 3, 8] → [2, 3, 4]
~~~

这里每个位置最终都得到 4 个分数，分别对应词表中的 4 个 token。

### 3. Logits、Loss 与参数更新

Linear 输出的是 logits，也就是还没有归一化的分数。对同一个位置来说，logit 越高，模型越倾向于预测对应的 token。Softmax 可以把一组 logits 转换成概率：

    probabilities = softmax(logits)

转换后的每个概率都大于 0，所有候选 token 的概率加起来等于 1；推理时可以用 `logits.argmax(dim=-1)` 取分数最高的 token ID，再交给 Tokenizer 的 `decode` 转回文本。训练时通常不需要手动调用 Softmax，因为 PyTorch 的 `F.cross_entropy` 内部已经包含了 `log_softmax` 和负对数似然损失，应该直接传入 logits：

    loss = F.cross_entropy(logits, targets)

这里有一个很容易踩到的 shape 细节。对于单个位置，`logits` 是 `[V]`，目标是一个整数标量；对于已经摊平的一批位置，`logits` 是 `[N, V]`，目标是 `[N]`。而语言模型通常保留 `[B, T, V]` 的形状，这时需要把 `B` 和 `T` 合并：

~~~python
# logits:  [B, T, V]
# targets: [B, T]
loss = F.cross_entropy(
    logits.reshape(B * T, V),
    targets.reshape(B * T),
)
~~~

也可以把类别维度换到 PyTorch 交叉熵期望的第 2 个维度：

~~~python
loss = F.cross_entropy(logits.transpose(1, 2), targets)
# logits.transpose(1, 2): [B, V, T]
~~~

训练一个神经网络就是不断调整参数，让正确目标 token 的分数更高。基本流程是：先前向计算得到 logits，再计算 loss；然后 `backward()` 根据计算图求出每个参数的梯度，优化器根据梯度更新参数。`zero_grad()` 用来清除上一步积累的梯度，通常放在每一轮开始的位置：

~~~python
optimizer.zero_grad()
logits = model(x)
loss = F.cross_entropy(logits, y)
loss.backward()
optimizer.step()
~~~

`nn.Module` 中的可学习参数默认会参与梯度计算，不需要手动给每个参数设置 `requires_grad=True`。评估或预测时可以使用 `with torch.no_grad()` 暂停梯度记录，节省内存。

### 4. 一个极小语言模型

下面的模型只学习四条独立的映射：

    猫 → 睡觉
    狗 → 跑步
    睡觉 → <结束>
    跑步 → <结束>

这里的 `x` 和 `y` 不是一条需要理解上下文的长句，而是四个训练样本。模型收到一个 token ID 后，经过 Embedding 和 Linear，输出整个词表的 logits，再用正确的下一个 token 计算 loss。保存为 `tiny_lm.py` 后，可以使用 `uv run python tiny_lm.py` 执行：

~~~python
import torch
from torch import nn
from torch.nn import functional as F

torch.manual_seed(0)

vocab = {
    "猫": 0,
    "狗": 1,
    "睡觉": 2,
    "跑步": 3,
    "<结束>": 4,
}
id_to_token = {i: token for token, i in vocab.items()}

x = torch.tensor(
    [vocab["猫"], vocab["狗"], vocab["睡觉"], vocab["跑步"]],
    dtype=torch.long,
)
y = torch.tensor(
    [vocab["睡觉"], vocab["跑步"], vocab["<结束>"], vocab["<结束>"]],
    dtype=torch.long,
)


class TinyLanguageModel(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.linear = nn.Linear(embedding_dim, vocab_size)

    def forward(self, token_ids):
        hidden = self.embedding(token_ids)
        logits = self.linear(hidden)
        return logits


model = TinyLanguageModel(vocab_size=len(vocab), embedding_dim=3)
optimizer = torch.optim.Adam(model.parameters(), lr=0.1)

for step in range(500):
    optimizer.zero_grad()

    logits = model(x)              # [4] → [4, 5]
    loss = F.cross_entropy(logits, y)

    loss.backward()
    optimizer.step()

    if step % 100 == 0:
        print(f"step={step}, loss={loss.item():.4f}")


with torch.no_grad():
    logits = model(x)
    predicted_ids = logits.argmax(dim=-1)

for input_id, target_id, predicted_id in zip(x, y, predicted_ids):
    print(
        f"{id_to_token[input_id.item()]} → "
        f"预测：{id_to_token[predicted_id.item()]}，"
        f"正确答案：{id_to_token[target_id.item()]}"
    )
~~~

这段代码把第一阶段的完整闭环串了起来：token ID 作为 Embedding 的行号，查出向量；Linear 为词表中每个候选 token 计算一个 logit；交叉熵根据正确答案评价这组分数；`backward()` 计算梯度，优化器再同时更新 Embedding 表和 Linear 的参数。

当前这个模型的问题在于：当前位置的表示只由当前位置的 token 决定。例如，对于“我 喜欢 猫”和“我 喜欢 狗”，在预测“喜欢”之后的 token 时，模型两次都只看到“喜欢”这一个 token，因此会产生完全相同的 logits，无法根据前文选择不同答案。这也就是 Transformer，尤其是 Attention 要解决的问题：让不同位置的信息互相交互，使当前位置的表示能够包含上下文。
