# 语言模型、Tokenizer、PyTorch

语言模型（Language Model）要解决的核心问题很简单：给定已经出现的内容，预测下一个 token。比如完整序列是：

    我 喜欢 猫 <结束>

训练时把同一个序列错开一位，得到输入和目标：

    输入 x： 我     喜欢    猫
    目标 y： 喜欢   猫      <结束>

也就是说，目标 token 总是输入 token 的下一个 token。对于真正能够理解上下文的模型，可以把这理解成：看到“我”后预测“喜欢”，看到“我 喜欢”后预测“猫”，看到“我 喜欢 猫”后预测“<结束>”。不过，下面要实现的极简模型还没有 Transformer，它实际上只能看到当前位置的 token，因此只能学习“我 → 喜欢”“喜欢 → 猫”这样的独立映射，暂时不能真正利用“我 喜欢”这个完整前缀。**这也是为什么 Transformer 如此重要的原因～**

整个过程可以先记成一条主链路：

    文本 → Tokenizer → token ID → Tensor
         → Embedding → 向量 → Linear → logits
         → loss → 梯度 → 更新参数

### 1. Tokenizer 与语言模型的训练数据

神经网络不能直接处理字符串，所以需要 Tokenizer 把文本切分成 token，再把每个 token 转换成整数编号：

    文本 → token → token ID

例如，某个词表可能规定：

    我 → 12，喜欢 → 35，猫 → 87

于是：

    encode("我喜欢猫") → [12, 35, 87]
    decode([12, 35, 87]) → "我喜欢猫"

`encode` 完成文本到 token ID 的转换，`decode` 完成 token ID 到文本的转换。Tokenizer 负责建立“字符串和整数编号”的对应关系，Embedding 才负责把整数编号转换成可学习的向量

最简单的字符级 Tokenizer 可以把每个字符作为一个 token。现代语言模型通常使用子词 Tokenizer（Subword Tokenizer），例如 BPE（Byte Pair Encoding）：常见的字符组合会逐渐合并成较大的 token，常见词可以用较少的 token 表示，生僻词仍然可以拆成更小的片段。词表中还经常有一些特殊 token，例如 `<unk>` 表示无法识别的 token，`<eos>` 表示序列结束，`<pad>` 用于把不同长度的序列补齐到同样长度。

Tokenizer 输出的是整数索引，所以传给 `nn.Embedding` 时通常使用 `torch.long`：

~~~python
token_ids = torch.tensor([12, 35, 87], dtype=torch.long)
~~~

语言模型训练时，通常会把很多条长度相同的 token 序列组成一个 batch。后面反复出现的几个字母约定如下：

    B：batch size，一次处理多少条序列
    T：sequence length，每条序列包含多少个位置
    D：embedding/hidden dimension，每个位置的向量长度
    V：vocabulary size，词表中 token 的数量

因此，一批输入通常是 `[B, T]`，目标也是 `[B, T]`；模型在每个位置都对整个词表进行预测，输出形状是 `[B, T, V]`。

### 2. Tensor、Embedding 与 Linear：从编号到词表分数

PyTorch Tensor 可以看成多维数值数组，但它还支持向量化运算、GPU 计算和自动求导。它的形状可以表示不同层次的数据：标量的 shape 是 `[]`，向量是 `[D]`，矩阵是 `[M, N]`，一批序列的向量则可以是 `[B, T, D]`。常用属性包括 `x.shape`、`x.ndim`、`x.dtype` 和 `x.device`。

Tensor 的索引从 0 开始。假设：

    token_ids = [
        [1, 3, 4],
        [2, 3, 5],
    ]

那么 `token_ids[0, 1]` 的结果是 `3`，表示第 0 句话的第 1 个位置，也就是第一句话的第二个 token 的 ID。

需要区分两种常见的乘法：`a * b` 是对应位置相乘，要求形状能够广播；`a @ b` 是矩阵乘法，例如 shape 为 `[4, 5]` 的矩阵乘 shape 为 `[5, 2]` 的矩阵，结果 shape 为 `[4, 2]`。中间的两个维度 `5` 必须匹配，外侧的 `4` 和 `2` 决定结果形状。（想起了线性代数一些不好的回忆......)

Embedding 可以理解成一张可学习的查表。假设词表有 `V` 个 token，每个 token 用 `D` 个数字表示：

    embedding = nn.Embedding(num_embeddings=V, embedding_dim=D)
    embedding.weight.shape == [V, D]

表的第 `i` 行就是 token ID 为 `i` 的向量。如果 `token_ids[0, 1] == 3`，那么：

    embedding(token_ids)[0, 1] == embedding.weight[3]

也就是说，Embedding 不是根据 token ID 做复杂计算，而是根据 ID 取出对应的那一行。假设输入 `token_ids` 的 shape 是 `[2, 3]`，查表后输出的 shape 就是 `[2, 3, D]`：原来的每个整数位置，都被替换成了一个 `D` 维向量。

这些向量一开始通常是随机的，训练过程中会根据 loss 产生的梯度逐渐调整。向量的价值在于它是连续的数值表示，后面的 Linear 等层可以对它做点积、加权和并通过梯度学习

Linear 接着把每个 `D` 维向量转换成 `V` 个数字。因为 `out_features` 被设置成词表大小，所以这 `V` 个数字可以按照词表编号解释（注意是人为地去“解释”哦）为每个候选 token 的分数：

    linear = nn.Linear(in_features=D, out_features=V)
    [B, T, D] → [B, T, V]

Linear 本身并不知道“第 0 个输出代表哪个词”，它只负责输出数字；是词表 ID 的约定让我们把第 `i` 个输出解释成 token `i` 的分数。对于一个输入向量 `h`，PyTorch 中 Linear 的参数形状通常是：

    linear.weight： [V, D]
    linear.bias：   [V]

**如果把输入写成列向量**（这个数学变形很重要，不能忽略），计算可以写成 `logits = W @ h + b`；如果把输入写成行向量，则写成 `logits = h @ W.T + b`。展开来看，第 `i` 个候选 token 的分数就是：

    logits[i] = h · W[i] + b[i]

因此，`W` 的每一行都可以看成一个候选 token 的独立打分器。具体地，假设：

    h = [2, -1, 0.5]

    W =
    [
        [ 1,  0, 2],   # token 0
        [ 0,  1, 1],   # token 1
        [ 0, -1, 2],   # token 2
        [-1,  1, 0],   # token 3
    ]

忽略 bias 时，四个分数分别是：

    token 0：2×1 + (-1)×0 + 0.5×2 = 3
    token 1：2×0 + (-1)×1 + 0.5×1 = -0.5
    token 2：2×0 + (-1)×(-1) + 0.5×2 = 2
    token 3：2×(-1) + (-1)×1 + 0.5×0 = -3

所以 `logits = [3, -0.5, 2, -3]`，分数最高的是 token 0。Linear 并不是把一个向量直接“变成了某个 token”，而是用 `V` 套不同的打分公式，同时评估词表中的 `V` 个候选 token。对 `[B, T, D]` 的输入，Linear 会对最后一个维度独立执行同样的计算，所以每个 batch、每个位置都会得到一组 `[V]` 分数。

把两层连起来看，代码和形状就是：

~~~python
import torch
from torch import nn

B, T, V, D = 2, 3, 4, 8
token_ids = torch.tensor([[0, 1, 2], [1, 2, 3]], dtype=torch.long)

embedding = nn.Embedding(num_embeddings=V, embedding_dim=D)
linear = nn.Linear(in_features=D, out_features=V)

hidden = embedding(token_ids)  # [2, 3]     → [2, 3, 8]
logits = linear(hidden)        # [2, 3, 8] → [2, 3, 4]
~~~

这里每个位置最终都得到 4 个分数，分别对应词表中的 4 个 token。

### 3. Logits、Loss 与参数更新

Linear 输出的是 logits，也就是还没有归一化的分数。对同一个位置来说，logit 越高，模型越倾向于预测对应的 token。Softmax 可以把一组 logits 转换成概率：

    probabilities = softmax(logits)

转换后的每个概率都大于 0，所有候选 token 的概率加起来等于 1；推理时可以用 `logits.argmax(dim=-1)` 取分数最高的 token ID，再交给 Tokenizer 的 `decode` 转回文本。训练时通常不需要手动调用 Softmax，因为 PyTorch 的 `F.cross_entropy` 内部已经包含了 `log_softmax` 和负对数似然损失，应该直接传入 logits：

    loss = F.cross_entropy(logits, targets)

这里有一个很容易踩到的 shape 细节。对于单个位置，`logits` 是 `[V]`，目标是一个整数标量；对于已经摊平的一批位置，`logits` 是 `[N, V]`，目标是 `[N]`。而语言模型通常保留 `[B, T, V]` 的形状，这时需要把 `B` 和 `T` 合并：

~~~python
# logits:  [B, T, V]
# targets: [B, T]
loss = F.cross_entropy(
    logits.reshape(B * T, V),
    targets.reshape(B * T),
)
~~~

也可以把类别维度换到 PyTorch 交叉熵期望的第 2 个维度：

~~~python
loss = F.cross_entropy(logits.transpose(1, 2), targets)
# logits.transpose(1, 2): [B, V, T]
~~~

训练一个神经网络就是不断调整参数，让正确目标 token 的分数更高。基本流程是：先前向计算得到 logits，再计算 loss；然后 `backward()` 根据计算图求出每个参数的梯度，优化器根据梯度更新参数。`zero_grad()` 用来清除上一步积累的梯度，通常放在每一轮开始的位置：

~~~python
optimizer.zero_grad()
logits = model(x)
loss = F.cross_entropy(logits, y)
loss.backward()
optimizer.step()
~~~

`nn.Module` 中的可学习参数默认会参与梯度计算，不需要手动给每个参数设置 `requires_grad=True`。评估或预测时可以使用 `with torch.no_grad()` 暂停梯度记录，节省内存。

### 4. 一个极小语言模型

下面的模型只学习四条独立的映射：

    猫 → 睡觉
    狗 → 跑步
    睡觉 → <结束>
    跑步 → <结束>

这里的 `x` 和 `y` 不是一条需要理解上下文的长句，而是四个训练样本。模型收到一个 token ID 后，经过 Embedding 和 Linear，输出整个词表的 logits，再用正确的下一个 token 计算 loss。保存为 `tiny_lm.py` 后，可以使用 `uv run python tiny_lm.py` 执行：

~~~python
import torch
from torch import nn
from torch.nn import functional as F

torch.manual_seed(0)

vocab = {
    "猫": 0,
    "狗": 1,
    "睡觉": 2,
    "跑步": 3,
    "<结束>": 4,
}
id_to_token = {i: token for token, i in vocab.items()}

x = torch.tensor(
    [vocab["猫"], vocab["狗"], vocab["睡觉"], vocab["跑步"]],
    dtype=torch.long,
)
y = torch.tensor(
    [vocab["睡觉"], vocab["跑步"], vocab["<结束>"], vocab["<结束>"]],
    dtype=torch.long,
)


class TinyLanguageModel(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.linear = nn.Linear(embedding_dim, vocab_size)

    def forward(self, token_ids):
        hidden = self.embedding(token_ids)
        logits = self.linear(hidden)
        return logits


model = TinyLanguageModel(vocab_size=len(vocab), embedding_dim=3)
optimizer = torch.optim.Adam(model.parameters(), lr=0.1)

for step in range(500):
    optimizer.zero_grad()

    logits = model(x)              # [4] → [4, 5]
    loss = F.cross_entropy(logits, y)

    loss.backward()
    optimizer.step()

    if step % 100 == 0:
        print(f"step={step}, loss={loss.item():.4f}")


with torch.no_grad():
    logits = model(x)
    predicted_ids = logits.argmax(dim=-1)

for input_id, target_id, predicted_id in zip(x, y, predicted_ids):
    print(
        f"{id_to_token[input_id.item()]} → "
        f"预测：{id_to_token[predicted_id.item()]}，"
        f"正确答案：{id_to_token[target_id.item()]}"
    )
~~~

这段代码把第一阶段的完整闭环串了起来：token ID 作为 Embedding 的行号，查出向量；Linear 为词表中每个候选 token 计算一个 logit；交叉熵根据正确答案评价这组分数；`backward()` 计算梯度，优化器再同时更新 Embedding 表和 Linear 的参数。

当前这个模型的问题在于：当前位置的表示只由当前位置的 token 决定。例如，对于“我 喜欢 猫”和“我 喜欢 狗”，在预测“喜欢”之后的 token 时，模型两次都只看到“喜欢”这一个 token，因此会产生完全相同的 logits，无法根据前文选择不同答案。这也就是 Transformer，尤其是 Attention 要解决的问题：让不同位置的信息互相交互，使当前位置的表示能够包含上下文。

# 单头注意力机制

第一阶段的极小语言模型只能根据当前位置的 token 做预测，无法利用前面的上下文。**所以我们在谈论 Attention 时究竟在谈论什么**：对于序列中的每个位置，让模型动态地从其他位置找到相关信息，再把这些信息汇总到当前位置，这就是所谓的“注意力”。例如，在“我 喜欢 猫”中，模型处理“喜欢”时，可以根据当前需求关注“我”或“猫”；在自回归语言模型中，还必须限制它不能看到未来位置，也就是看到“猫”这个位置～

## 1. Q、K、V 是什么

假设经过 Embedding 或前一层 Transformer 后，三个 token 的隐藏向量组成矩阵 `X`：

    X shape = [T, D]

其中 `T` 是 token 数量，`D` 是每个隐藏向量的维度。Q、K、V 不是 token 自带的三个固定属性，也不是凭空写出来的向量；它们是由当前输入 `X` 经过三个不同的、可学习的 Linear 投影得到的：

    Q = X @ W_Q + b_Q    # Query，当前 token 想寻找什么
    K = X @ W_K + b_K    # Key，每个 token 能提供什么信息
    V = X @ W_V + b_V    # Value，每个 token 实际提供的内容

这里的 `@` 是矩阵乘法。若采用 PyTorch 的行向量写法，三个投影通常可以写成：

~~~python
q_proj = nn.Linear(D, d_k)
k_proj = nn.Linear(D, d_k)
v_proj = nn.Linear(D, d_v)

Q = q_proj(X)  # [T, D] → [T, d_k]
K = k_proj(X)  # [T, D] → [T, d_k]
V = v_proj(X)  # [T, D] → [T, d_v]
~~~

`d_k` 是 Query/Key 的维度，`d_v` 是 Value 的维度。为了帮助理解，可以暂时手动设置投影矩阵，例如令 `W_Q` 和 `W_K` 为单位矩阵时，`Q` 和 `K` 恰好等于输入向量；令 `W_V` 为其他矩阵时，`V` 就是输入向量经过另一种变换后的结果。

到底如何理解 Q，K，V 呢，我认为：`Q` 像“我现在想找什么信息”，`K` 像“我这里有什么特征，值得不值得被关注”，`V` 像“如果你关注我，我真正传给你的内容”。同一个 token 的 Q、K、V 都来自同一个输入向量，但使用不同的 Linear 参数，因此承担不同角色。

## 2. 用 Q 和 K 计算注意力分数

第 `i` 个 token 的 Query 需要和所有 token 的 Key 比较，得到它应该关注每个位置的程度。比较使用的是**向量点乘**：

    score[i, j] = Q[i] · K[j]

向量点乘会先逐元素相乘，再求和。例如：

    [2, 1] · [2, 1] = 2×2 + 1×1 = 5

点乘结果越大，说明当前 Query 与这个 Key 的匹配度越高。它可以直观理解成相似度，但更准确地说是模型学习出来的“匹配分数”，因为 Q、K 都经过了可学习的投影。

如果逐个计算所有 Query-Key 的点乘会很慢，矩阵乘法可以一次性完成这件事：

    scores = Q @ K.T

假设：

    Q shape   = [T, d_k]
    K shape   = [T, d_k]
    K.T shape = [d_k, T]

则：

    scores shape = [T, T]

`K.T` 表示 `K` 的转置，即交换行和列。`K` 的每一行是一个 Key，转置后每一列是一个 Key；因此按照矩阵乘法“左边的一行和右边的一列做点乘”的规则：

    scores[i, j] = Q[i] · K[j]

这里整体的 `Q @ K.T` 是**矩阵乘法**，结果中的每个元素本质上是一个**向量点乘**。这里当时也卡了我有点久，不过理解透彻矩阵乘法和为什么要转置 K，这个小式子也就不难理解了～～

## 3. 为什么除以 `sqrt(d_k)`，以及如何得到权重

原始分数还要进行缩放：

    scaled_scores = (Q @ K.T) / sqrt(d_k)

这里 `/ sqrt(d_k)` 是用一个标量除法，把所有分数统一缩小。因为 Query/Key 的维度 `d_k` 越大，点乘中累加的项越多，分数的典型数值规模大约会随着 `sqrt(d_k)` 变大。如果不缩放，后面的 softmax 可能变得过于尖锐，几乎只选择一个位置，导致训练不稳定、梯度变小。

除以同一个正数不会改变分数的大小顺序，主要作用是控制数值规模。然后对每个 Query 所对应的一行分数做 softmax：

    weights = softmax(scaled_scores, dim=-1)

    weights shape = [T, T]

`weights[i, j]` 表示第 `i` 个位置对第 `j` 个位置的注意力权重。同一行的权重加起来等于 1，因此可以把它理解成“第 `i` 个位置如何在所有位置之间分配注意力”。

## 4. 用权重汇总 Value

得到注意力权重后，使用它们对所有 Value 做加权求和：

    output = weights @ V

这里的 `@` 是**矩阵乘法**：左边矩阵的一行和右边矩阵的一列做向量点乘。具体地，`output[i, r] = weights[i, :] · V[:, r]`。利用分配律，把每个输出维度的计算合在一起，就等价于下面对 Value 行向量做加权求和（其实这里也是一个数学变形，原来的矩阵乘法一行对应一列去乘，而下面这种写法也是正确的）：

    output[i] = weights[i, 0] × V[0]
              + weights[i, 1] × V[1]
              + ...
              + weights[i, T-1] × V[T-1]

上式中的 `weights[i, j] × V[j]` 是**标量乘向量**，表示把一个 Value 向量按权重缩放；不同位置的结果再做向量加法。shape 为：

    weights: [T, T]
    V:       [T, d_v]
    output:  [T, d_v]

例如，假设有两个 Query、三个来源 token，并且每个 Value 向量有两个维度：

    weights =
    [
        [0.2, 0.5, 0.3],   # Query 0 对三个 token 的权重
        [0.6, 0.1, 0.3],   # Query 1 对三个 token 的权重
    ]                       # [2, 3]

    V =
    [
        [10, 1],             # V[0]
        [20, 2],             # V[1]
        [30, 3],             # V[2]
    ]                       # [3, 2]

进行**矩阵乘法**：

    weights @ V =
    [
        [0.2×10 + 0.5×20 + 0.3×30,
         0.2×1  + 0.5×2  + 0.3×3],
        [0.6×10 + 0.1×20 + 0.3×30,
         0.6×1  + 0.1×2  + 0.3×3],
    ]
    =
    [
        [21, 2.1],
        [17, 1.7],
    ]

例如，左边第一行和右边第一列做**向量点乘**：

    output[0, 0] = [0.2, 0.5, 0.3] · [10, 20, 30] = 21

同一个结果也可以从“加权汇总 Value”的角度理解：

    output[0] = 0.2×V[0] + 0.5×V[1] + 0.3×V[2]
              = 0.2×[10, 1] + 0.5×[20, 2] + 0.3×[30, 3]
              = [21, 2.1]

这里展开式中的 `×` 是**标量乘向量**，而最外层的 `weights @ V` 是**矩阵乘法**；两种写法只是同一个计算的不同数学表达。

这里的 `output`（有时也写成 `outputs`）是 Attention 层真正产生的结果：每个位置把自己关注到的 Value 信息按权重汇总后，得到一个新的上下文向量。它不是 token ID，也不是概率，而是一个包含上下文的隐藏表示。`output[i]` 对应第 `i` 个 token；如果某个位置同时关注了“我”“喜欢”和“猫”，它的输出就会融合这几个位置的信息，而不再只是当前位置自己的向量。

因此，Attention 的作用不是直接选出一个 token，而是先让每个位置获得上下文信息，再把这些更丰富的向量交给后续层。对于语言模型，通常会继续用词表 Linear 把它们转换为 logits：

    logits = output @ W_vocab.T + b

这里的 `@` 仍然是**矩阵乘法**，它把每个位置的上下文向量转换成整个词表的分数，之后才能计算 loss 或进行预测。换句话说，`weights` 决定“从哪里获取信息”，`V` 提供“具体内容”，`output` 则是“融合上下文之后的表示”。

因此，完整的 Scaled Dot-Product Attention 公式是：

    Attention(Q, K, V)
      = softmax((Q @ K.T) / sqrt(d_k)) @ V

逐步看就是：

    Q、K、V = 输入 X 经过三个不同的 Linear 投影
    Q @ K.T = 用矩阵乘法批量计算所有 Query-Key 的向量点乘分数
    / sqrt(d_k) = 控制分数规模
    softmax = 把分数转换成注意力权重
    weights @ V = 按权重对 Value 做加权汇总

## 5. Causal Mask：语言模型不能偷看未来

普通自注意力会让每个位置看到所有位置，但自回归语言模型训练时，第 `i` 个位置只能使用当前位置及其之前的信息，不能看到未来 token，否则训练时就会把答案直接偷看出来。

例如，序列长度为 4 时，允许关注的位置可以表示为：

    [1, 0, 0, 0]
    [1, 1, 0, 0]
    [1, 1, 1, 0]
    [1, 1, 1, 1]

第 0 行只能看第 0 个位置，第 1 行可以看第 0、1 个位置，以此类推。计算完 `Q @ K.T` 后，把未来位置对应的分数设为负无穷：

~~~python
# Q: [T, d_k]，K: [T, d_k]；先做矩阵乘法，结果中每个元素是一个 Query-Key 点乘
# 再除以 sqrt(d_k) 这个标量，控制点乘分数的数值规模
scores = Q @ K.T / math.sqrt(d_k)

# 创建一个 [T, T] 的全 True 布尔矩阵，先把所有位置都标记为“需要屏蔽”
future_mask = torch.triu(
    torch.ones(T, T, dtype=torch.bool),  # 生成 [T, T] 的布尔矩阵
    diagonal=1,                          # 只保留主对角线以上的区域，也就是未来位置
)  # 得到上三角的 causal mask；mask[i, j] 为 True 表示位置 i 不能看位置 j

# 把未来位置的分数替换成负无穷；softmax 后这些位置的权重会变成 0
scores = scores.masked_fill(future_mask, float("-inf"))

# 沿最后一个维度做 softmax，即每个 Query 对所有 Key 的分数单独归一化
weights = torch.softmax(scores, dim=-1)

# weights: [T, T]，V: [T, d_v]；做矩阵乘法，按权重汇总所有 Value
output = weights @ V
~~~

softmax 遇到负无穷时，对应位置的权重会变成 0，于是未来 token 不会参与当前 token 的信息汇总。注意：mask 通常加在 softmax 之前；如果在 softmax 之后再把权重设为 0，就需要额外重新归一化。

## 6. 最小代码示例

下面的代码固定了 Q、K、V 的投影参数，便于观察每一步的结果。真实 Transformer 中这些投影参数是随机初始化后通过训练学习的：

~~~python
import math
import torch
from torch import nn

torch.manual_seed(0)

T, D, d_k, d_v = 3, 2, 2, 2
X = torch.tensor([
    [1.0, 2.0],  # token 0
    [2.0, 1.0],  # token 1
    [0.0, 1.0],  # token 2
])

q_proj = nn.Linear(D, d_k, bias=False)
k_proj = nn.Linear(D, d_k, bias=False)
v_proj = nn.Linear(D, d_v, bias=False)

with torch.no_grad():
    q_proj.weight.copy_(torch.eye(2))
    k_proj.weight.copy_(torch.eye(2))
    v_proj.weight.copy_(torch.tensor([
        [2.0, 0.0],
        [0.0, 1.0],
    ]))

Q = q_proj(X)                         # [3, 2]
K = k_proj(X)                         # [3, 2]
V = v_proj(X)                         # [3, 2]

scores = Q @ K.T / math.sqrt(d_k)     # 矩阵乘法 + 标量除法
mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(mask, float("-inf"))

weights = torch.softmax(scores, dim=-1)  # 每行做 softmax
output = weights @ V                      # 矩阵乘法

print("Q =", Q)
print("K =", K)
print("V =", V)
print("scores =", scores)
print("weights =", weights)
print("output =", output)
~~~

这个例子里，`q_proj`、`k_proj`、`v_proj` 都是内部投影层，它们的输出不是词表分数；最后将 Transformer 的隐藏状态映射到词表 logits 的 `nn.Linear(D, V)` 才是语言模型的输出层。单头注意力只产生一组 Q、K、V 和一张注意力权重矩阵；多头注意力会并行使用多组投影，让不同的头学习不同类型的 token 关系。

# 多头注意力、位置编码与 Pre-LN Transformer Block

## 1. Transformer 中常见的 shape

Transformer 通常用三维张量表示一批序列：

    [B, T, d_model]

其中：

    B：batch size，一次处理多少句话
    T：sequence length，每句话有多少个 token 位置
    d_model：每个 token 的隐藏向量有多少个特征

例如 `[2, 3, 8]` 表示 2 句话、每句话 3 个 token、每个 token 用 8 个数字表示。可以把它看成 2 个 `[3, 8]` 的矩阵：

    x[0]       shape = [3, 8]   # 第 0 句话
    x[0, 1]    shape = [8]      # 第 0 句话的第 1 个 token
    x[0, 1, 2] shape = []       # 一个具体的标量

这里的最后一个维度通常是“特征维度”，而 `T` 是“位置维度”。很多 Transformer 操作都保持 `[B, T, d_model]` 不变，只是在每个位置上不断更新 token 的隐藏表示。

## 2. 多头注意力（Multi-Head Attention）

单头注意力只有一组 Q、K、V。多头注意力则使用多个 head 并行地做单头注意力，让不同的 head 学习不同类型的关系。例如，一个 head 可以关注主语，另一个 head 可以关注相邻词。

假设：

    d_model = 8
    H = 2          # head 数量
    d_head = 4     # 每个 head 的维度

满足：

    d_model = H × d_head = 2 × 4 = 8

输入 `x` 的 shape 是 `[B, T, 8]`。通常先用 Linear 得到 Q、K、V，它们仍然是：

    Q、K、V: [B, T, d_model] = [B, T, 8]

然后把最后一个维度拆成 head 维和每个 head 的特征维：

    [B, T, d_model]
    → [B, T, H, d_head]
    → [B, H, T, d_head]

`transpose` 调整维度顺序。调整后，`Q[b, h]` 就是第 `b` 个样本、第 `h` 个 head 的一个 `[T, d_head]` 矩阵。

对于每个 batch 和每个 head，计算注意力分数：

    Q:                       [B, H, T, d_head]
    K.transpose(-2, -1):     [B, H, d_head, T]
    Q @ K.transpose(-2, -1): [B, H, T, T]

这里的 `@` 是批量矩阵乘法。它实际上对每个 `b`、每个 `h` 分别进行：

    [T, d_head] @ [d_head, T] → [T, T]

然后经过缩放、Causal Mask 和 softmax 得到 `weights`，再汇总 Value：

    weights: [B, H, T, T]
    V:       [B, H, T, d_head]
    weights @ V → [B, H, T, d_head]

最后把 head 维和每个 head 的特征维合并：

    [B, H, T, d_head]
    → [B, T, H, d_head]
    → [B, T, H × d_head]
    = [B, T, d_model]

这里是沿着最后的特征维进行拼接，也就是拼接“列”，而不是拼接 token 的行。对于同一个 token，所有 head 的输出会被放在一起，扩展这个 token 的表示。

## 3. LayerNorm、残差连接与 FFN

### LayerNorm

对 `[B, T, d_model]` 的输入，LayerNorm 通常只在最后一个 `d_model` 维度上做标准化：每个 token 单独处理自己的特征，不会把不同 token 混在一起。

对某个 token 的向量 `x`：

    mean = x 的平均值
    variance = x 的方差
    normalized = (x - mean) / sqrt(variance + epsilon)
    output = gamma * normalized + beta

这里 `gamma` 和 `beta` 是可学习参数，`*` 是逐元素乘法。LayerNorm 不改变 shape：

    [B, T, d_model] → [B, T, d_model]

### 残差连接

残差连接就是把子层的输出加回原输入：

    x_new = x + sublayer_output

这里的 `+` 是逐元素相加，要求两个张量 shape 相同。它让原始信息可以直接保留下来，同时让子层只需要学习“在原表示上增加什么信息”。

### FFN（Feed-Forward Network）

FFN 也叫 MLP，通常由两个 Linear 和一个激活函数组成：

    FFN(x) = Linear_2(activation(Linear_1(x)))

例如：

    [B, T, d_model]
    → Linear(d_model, d_ff)
    [B, T, d_ff]
    → GELU 或 ReLU
    [B, T, d_ff]
    → Linear(d_ff, d_model)
    [B, T, d_model]

Attention 和 FFN 的职责不同：

    Attention：在不同 token 位置之间传递、混合上下文信息
    FFN：每个位置独立处理自己的特征，不和其他位置通信

因此，Attention 主要混合 `T` 这个位置维度，FFN 主要混合每个 token 内部的 `d_model` 个特征。

## 4. 位置编码与 RoPE

Token Embedding 只告诉模型“这个 token 是什么”，并不会告诉模型“它在第几个位置”。如果同一个 token 出现在不同位置，单独经过 Token Embedding 得到的向量是相同的。

最直观的相加式位置编码是：

    H = Token Embedding + Position Embedding

这里的 `+` 是逐元素相加。假设两者 shape 都是 `[T, d_model]`，结果仍然是 `[T, d_model]`；在 batch 中，位置向量通常广播到每句话：

    [B, T, d_model] + [T, d_model] → [B, T, d_model]

它相当于同时告诉模型：

    Token Embedding：我是谁？
    Position Embedding：我在哪里？

Causal Mask 和位置编码不是一回事：

    位置编码：提供位置、顺序和距离信息
    Causal Mask：限制当前位置不能看到未来位置

现代许多 decoder-only 大语言模型使用 RoPE（Rotary Position Embedding）。RoPE 通常不把位置向量直接加到输入 `x` 上，而是在 Attention 内部根据位置旋转 Q 和 K，V 通常不旋转。

对于一对特征 `[x_even, x_odd]`，RoPE 的旋转结果是：

    x_even' = x_even × cos(theta) - x_odd × sin(theta)
    x_odd'  = x_even × sin(theta) + x_odd × cos(theta)

这里 `×` 是标量乘法。

例如：

    [1, 0] 在旋转 90° 后变成 [0, 1]

如果 Query 和 Key 位于不同位置，它们会被旋转不同角度，再进行点乘：

    Q_rotated · K_rotated

因此点乘结果会包含两个位置之间的相对位置信息。RoPE 不改变 Q、K 的 shape：

    Q、K:         [B, H, T, d_head]
    Q_rotated、K_rotated: [B, H, T, d_head]

RoPE 的核心代码结构可以简化为：

~~~python
def apply_rope(x, theta):
    # x: [B, H, T, d_head]
    # theta: [T, d_head // 2]
    B, H, T, d_head = x.shape

    # 把最后一个维度两两分组；这里只调整 shape，不做乘法
    x = x.reshape(B, H, T, d_head // 2, 2)

    # [T, d_head // 2] → [1, 1, T, d_head // 2, 1]
    # 前两个维度会广播到所有 batch 和所有 head
    cos = theta.cos()[None, None, :, :, None]
    sin = theta.sin()[None, None, :, :, None]

    # 对 [x_even, x_odd] 构造 [-x_odd, x_even]
    rotated = torch.stack((-x[..., 1], x[..., 0]), dim=-1)

    # * 是逐元素乘法，+ 是逐元素相加
    return (x * cos + rotated * sin).flatten(-2)
~~~

在 Attention 中：

~~~python
Q_rotated = apply_rope(Q, theta)
K_rotated = apply_rope(K, theta)

# @ 是批量矩阵乘法
scores = Q_rotated @ K_rotated.transpose(-2, -1)
~~~

## 5. Pre-LN Transformer Block

Pre-LN 的意思是：在 Attention 或 FFN 之前先做 LayerNorm。一个 Block 的核心计算可以写成：

    x1 = x + Attention(LayerNorm(x))
    x2 = x1 + FFN(LayerNorm(x1))

如果使用 RoPE，它位于 `Attention` 内部，主要对 Q、K 做旋转：

    x
    ↓ LayerNorm
    ↓ Q、K、V 投影
    ↓ 对 Q、K 应用 RoPE
    ↓ Q @ K.T、缩放、Causal Mask、softmax
    ↓ weights @ V
    ↓ 多头拼接与输出 Linear
    ↓ 与 x 做残差连接
    ↓ LayerNorm
    ↓ FFN
    ↓ 与前一步结果做残差连接

可以把它概括为：

    标准化
    → Attention 混合上下文信息
    → 残差连接
    → 标准化
    → FFN 处理每个 token 自己的特征
    → 残差连接

多个 Transformer Block 堆叠后，最后通常再经过 LayerNorm 和词表 Linear：

    [B, T, d_model]
    → Linear(d_model, vocab_size)
    → [B, T, vocab_size]

这个 `[B, T, vocab_size]` 才是每个位置对词表中所有 token 的 logits。

## 6. 计算图、反向传播与优化器

训练神经网络可以分成前向传播和反向传播：前向传播根据当前参数计算预测值和 loss；反向传播从 loss 出发，沿计算图反方向计算每个参数的梯度。

先看一个只有一个参数 `w` 的模型：

    pred = w × x
    loss = (pred - target)²

假设 `w=2、x=3、target=10`，则 `pred=6、error=-4、loss=16`。反向传播使用链式法则：

    ∂loss / ∂pred = 2 × (pred - target) = -8
    ∂pred / ∂w = x = 3
    ∂loss / ∂w = -8 × 3 = -24

`w.grad=-24` 表示增大 `w` 会让 loss 倾向于下降。PyTorch 会在前向计算时记录计算图，`loss.backward()` 沿图计算梯度并写入参数的 `.grad`，但不会直接更新参数。

最简单的梯度下降更新是：

    parameter_new = parameter - learning_rate × gradient

例如学习率为 `0.1` 时，`w_new = 2 - 0.1 × (-24) = 4.4`。这里的 `×` 是标量乘法，不是矩阵乘法。

训练循环中的三行代码分别表示：

    optimizer.zero_grad()：清除上一轮积累的梯度
    loss.backward()：计算当前 loss 对所有参数的梯度
    optimizer.step()：根据优化器规则更新所有参数

PyTorch 默认会累积梯度；如果不调用 `zero_grad()`，下一次 `backward()` 得到的梯度通常会和旧梯度相加。

一个最小线性回归模型可以学习 `y=3x+2`：

~~~python
import torch
from torch import nn

torch.manual_seed(0)
x = torch.tensor([[1.0], [2.0], [3.0], [4.0]])  # [4, 1]
y = 3 * x + 2  # 标量与张量的逐元素乘法；y: [4, 1]

model = nn.Linear(1, 1)  # 内部近似计算 x @ W.T + b
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

for step in range(1000):
    optimizer.zero_grad()
    prediction = model(x)          # [4, 1]
    loss = loss_fn(prediction, y)  # 标量 loss
    loss.backward()
    optimizer.step()

print(model.weight.item())  # 接近 3
print(model.bias.item())    # 接近 2
~~~

这个线性回归和 Transformer 的训练流程完全相同，只是参数少得多。Transformer 中的 Embedding、Q/K/V 投影、FFN、LayerNorm 和词表 Linear 参数，也都通过同一张计算图得到梯度并更新。

SGD（通常指 Mini-batch SGD）只使用当前 batch 的梯度：

    θ_new = θ - η × g

它规则简单、额外状态少，但对学习率比较敏感，batch 梯度有噪声时可能抖动。Momentum SGD 会保存历史更新方向：

    v_t = μ × v_{t-1} + g_t
    θ_t = θ_{t-1} - η × v_t

这样可以减少抖动，并在持续一致的方向上加速。

Adam 可以理解为“带 Momentum，并为不同参数自适应调整步长”。它维护梯度移动平均和梯度平方的移动平均：

    m_t = β₁ × m_{t-1} + (1 - β₁) × g_t
    v_t = β₂ × v_{t-1} + (1 - β₂) × (g_t * g_t)

这里的 `*` 是逐元素乘法，例如 `[2, -3] * [2, -3] = [4, 9]`。经过偏差修正后，Adam 的更新可以简化理解为：

    θ_new = θ - η × m_hat / (sqrt(v_hat) + epsilon)

Adam 通常比较容易训练、收敛较快，但需要为每个参数保存 `m`、`v` 两份额外状态，显存开销更大。

AdamW 在 Adam 的基础上加入独立的 Weight Decay：

    θ ← θ - η × λ × θ

它把更新拆成“Adam 根据梯度更新”和“独立缩小参数”两部分。这样 weight decay 不会被 Adam 的自适应缩放混在梯度里，正则化效果更直接，因此在 Transformer 和大语言模型训练中很常见。

常见写法是：

~~~python
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
optimizer = torch.optim.AdamW(
    model.parameters(), lr=0.001, weight_decay=0.01
)
~~~

可以这样对比：

    SGD：只看当前梯度，按统一步长更新，省显存
    Momentum SGD：当前梯度加上历史更新方向
    Adam：根据梯度方向和大小，为每个参数自适应调整步长
    AdamW：Adam 加上独立的 Weight Decay，Transformer 中很常见

优化器不会改变 Transformer 的前向结构，也不会改变 Attention 或 FFN 的计算；它只改变 `optimizer.step()` 更新参数的方式。
